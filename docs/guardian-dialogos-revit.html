Guardián de diálogos del plugin Revit MCP

Comandos set_dialog_guard y get_dialog_log · diagnóstico del log "Failed to create command instance" · 2026-10-16

01Qué problema resuelve

Un diálogo modal de Revit (error de contorno de losa, Dialog_Revit_DocWarnDialog, pregunta de unir muros) congela el hilo de la interfaz y con él la cola de eventos externos. Cada llamada MCP posterior queda esperando a que alguien haga clic.

Hasta ahora el código enviado con send_code_to_revit suscribía sus propios manejadores. Si esa llamada vencía a los 120 s, el manejador quedaba suscrito sin nadie que lo quitara. Ahora el estado vive en el command set cargado: hay como máximo una suscripción por evento y siempre se puede apagar.

02Cómo funciona

1. ActivarEl agente llama set_dialog_guard con enabled: true.
2. Suscribir una vezUn evento externo suscribe DialogBoxShowing y, si se pide, FailuresProcessing. Repetir la llamada solo cambia la política.
3. ResponderCada diálogo recibe la respuesta de la política. Se prueban botones en orden hasta que Revit acepte uno.
4. Auditarget_dialog_log lee el registro sin pasar por la cola de Revit, así responde aunque Revit esté ocupado.
PolíticaPreguntas de unir / adjuntarResto de diálogos
no_for_join_questions (por defecto)NoCancelar
cancelCancelarCancelar
okOK o SíOK o Sí (acepta advertencias y conserva la edición)
  • Pregunta de unir se detecta por el texto del diálogo (join, attach, unir, adjuntar, enlazar...) o por un DialogId que contenga "join" o "attach".
  • Cancelar en un diálogo de error revierte solo la transacción que lo generó.
  • deleteWarnings: true borra las advertencias durante el procesamiento de fallas, antes de que lleguen a un diálogo. Los errores nunca se borran.
  • Mientras está activo también responde los diálogos del trabajo manual del usuario. Se apaga con enabled: false o al cerrar Revit.

04"Failed to create command instance": no es un desajuste

Diagnóstico. Esas líneas son el mensaje de éxito mal etiquetado. En plugin/Core/CommandManager.cs, justo después de RegisterCommand(command), el plugin heredado del upstream escribía con nivel [Info] el texto "Failed to create command instance [nombre]: RevitMCPCommandSet.dll". Una falla real sale con nivel [Error] y lleva el nombre completo del tipo y el mensaje de la excepción, no el nombre de la DLL.

EvidenciaResultado
Líneas [Error] o [Warning] en todos los logs desde abrilNinguna
Comandos en commandRegistry.json instalado38, todos habilitados, incluidos build_model_from_spec, export_view_image, analyze_clashes y format_schedules
Comandos que el servidor MCP envía y el registro no tieneNinguno
RevitMCPCommandSet.dll instalada frente a la compilada en el repoIdénticas (5 oct, 425 472 bytes)
RevitMCPPlugin.dll instalada frente a la compilada en el repoDesfasada: instalada 5 oct (47 616 bytes), repo 14 oct (48 640 bytes). Falta la corrección del socket bd5d4cb que lee mensajes JSON-RPC completos en vez de un solo bloque de 8 KB
Carpeta suelta Addins\2025\RevitMCPCommandSet\La escribe el SDK al compilar; Revit no la carga porque no tiene .addin

Corrección aplicada: la línea ahora dice "Registered command [nombre]". Para alinear: desplegar con install-addin.ps1, que copia plugin y command set juntos desde la misma compilación y registra los comandos que falten. El desfase real es el del plugin: llamadas grandes de send_code_to_revit (más de 8 KB) pueden llegar truncadas con lo instalado hoy.

05Despliegue (Revit cerrado)

Todo está compilado en Release R25 y el servidor MCP en server/build. Revit está abierto, así que no se instaló nada.

  1. Guardar o sincronizar los modelos abiertos y cerrar Revit 2025.
  2. Desde la raíz del repo:
    .\scripts\install-addin.ps1 -RevitVersion 2025
    Respalda lo instalado en %USERPROFILE%\mcp-revit-backups\, copia plugin y command set, y agrega set_dialog_guard y get_dialog_log a commandRegistry.json.
  3. Reiniciar el cliente MCP (Claude) para que lea las dos herramientas nuevas.
  4. Abrir Revit y pulsar "Revit MCP Switch". En el log nuevo deben aparecer 40 líneas "Registered command".

Cerrar Revit también elimina los manejadores que el código enviado con send_code_to_revit haya dejado suscritos en esta sesión.

06Cómo probarlo

  1. Activar y revisar el estado:
    node scripts/revit-call.mjs set_dialog_guard "{\"enabled\":true}" 30
node scripts/revit-call.mjs get_dialog_log "{}" 30
    Debe devolver enabled: true y dialogBoxShowingSubscribed: true.
  2. Repetir la activación y confirmar que nada cambia salvo la política (sigue habiendo una sola suscripción).
  3. Provocar un diálogo de advertencia: crear con send_code_to_revit dos muros superpuestos en una transacción sin preprocesador de fallas. Sin deleteWarnings el log muestra Dialog_Revit_DocWarnDialog con respuesta Cancel y la transacción se revierte.
  4. Repetir con {"enabled":true,"deleteWarnings":true}: el log muestra una entrada source: failure, warning deleted, y los muros quedan creados.
  5. Pregunta de unir: en la interfaz, mover un muro sobre otro o adjuntar un muro a un techo hasta que Revit pregunte; el log debe mostrar respuesta No.
  6. Apagar: set_dialog_guard {"enabled":false} y comprobar dialogBoxShowingSubscribed: false.
  7. Leer y limpiar: get_dialog_log {"clear":true}.

07Límites conocidos

  • Si Revit ya está bloqueado por un diálogo, set_dialog_guard vence a los 15 s y se aplica cuando Revit quede libre. get_dialog_log sí responde.
  • Algunos diálogos no aceptan respuesta por API; la entrada queda como none (Revit rejected ...) y el diálogo puede seguir abierto. Para esos sigue sirviendo scripts/revit-dialog-watcher.ps1.
  • El log vive en memoria: se pierde al cerrar Revit.
  • No se probó todavía dentro de Revit; solo está compilado.
